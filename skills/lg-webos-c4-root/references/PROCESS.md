# 过程与结果判断

## 1. 确认目标

在电视的支持或软件信息页面记录完整型号、软件版本与 webOS 版本。历史成功范围见 [验证记录](VERIFICATION.md)。确认电脑可以向电视提供临时 HTTP 文件，电视能够回访电脑的局域网地址；不要使用网关地址或不可达的虚拟网卡地址。

## 2. 默认 probe

`scripts/root_flow.py` 默认使用 `probe`。首次使用加 `--pair`，通过电视配对弹窗授权 SSAP，再调用 `ssap://system.launcher/launch`，以 `com.webos.app.tinybrowser` 为目标、`params.contentTarget` 指向电脑提供的页面。页面通过 `PalmServiceBridge` 调用下载服务，将探测文件写入可写目录。

这是本次采用的 tinybrowser 适配入口；上游原始示例的 `ssap://webapp/launchWebApp` 路径保留在来源研究中，未被作为本仓库当前工具入口。

该阶段不覆盖 `volatile.cache`，不自动重启或创建 root shell。下载服务的接受结果只属于下载阶段；若服务拒绝权限、路径或参数，就保留错误并停止后续阶段。不要把静态固件分析或一次 API 返回直接当成设备已取得 root。

## 3. stage 与冷启动

`stage` 写入用于一次启动验证的身份载荷；运行后先按本次标记清理启动入口，或在提供备份时将其隔离到非启动名，再进行恢复。目标路径为：

```text
/mnt/lg/cmn_data/var/cache/volatile.cache
```

在本次验证的系统上，该目录映射到 `/var/cache`。启动消费者执行该缓存脚本，因此断电重启后才可能触发。需要用户明确提供 `--acknowledge-cache-overwrite`，并预先理解 [恢复限制](RECOVERY.md)。

等待投递结果后，让电视彻底断电再重新开机，保持电脑端工具运行。默认等待为 600 秒，需要时可通过 `--timeout` 延长。普通电源键可能进入待机；操作系统没有重新启动时，不能据此判断启动阶段是否有效。工具不会替用户断电或自动重启电视。

指定 `--restore-cache` 时，载荷检查本次标记后，先将启动文件移到同目录的 `volatile.cache.disabled-<run-id>`。只有恢复文件下载、哈希校验和恢复成功后才继续。下载或校验失败会保留非启动的隔离副本，不创建证明文件、不启动 SSH；下次启动不会执行已隔离的副本。隔离失败或恢复时发现新的缓存文件，都应按恢复文档检查实际状态。

启动回报应包含真实进程身份。`uid=0` 是该执行进程具有 root 身份的证据；缺少回报也可能由网络尚未恢复、电脑端监听地址错误或临时服务退出造成。应区分投递失败、启动未执行和回调丢失，避免不加判断地反复覆盖缓存。

## 4. SSH 接入

`ssh` 在同一启动路径上配置用户提供的 SSH 公钥，并使用用户自行提供、与目标系统兼容的 Dropbear 服务器文件。工具不分发私钥，不下载未经用户选择的服务器文件，不提供共享密码。

实际可用性依次由文件投递结果、启动后的 root 身份、SSH 服务启动结果及使用个人私钥的登录结果确认。历史现场最后使用的端口为 2222。公开版本不自动创建永久启动服务，后续重启的持续性需要另行验证与管理。

## 5. 结束

先确认载荷对启动缓存的恢复或移除结果，再结束电脑临时服务。保存的运行数据仅在自己的电脑上保留。不要上传 `.local/`、配对信息、私钥、未脱敏日志或恢复文件。

完整参数以 `python scripts/root_flow.py --help` 为准。任何新固件上的表现都应作为一次新的验证记录，不应覆盖本文的历史范围。
