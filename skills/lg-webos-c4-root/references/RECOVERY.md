# 恢复与清理

## 覆盖前的限制

`stage` 与 `ssh` 要求显式传入 `--acknowledge-cache-overwrite`，因为它们会替换电视的 `volatile.cache`。下载接口不会提供原文件内容，本工具也不会在尚无读通道时自动取得原始备份。若该文件已经包含需要保留的内容，必须先通过自己已有的读取方式取得副本，并确认可恢复性。

历史现场的载荷在运行后删除自己的 `volatile.cache`，没有自动备份原文件。公开整理版会限定移除条件，并支持用户提供的恢复文件；这无法补回历史上未保存的文件内容。

## 提供已有备份

已有可信原文件时，为相应命令添加：

```sh
--restore-cache /path/to/original-volatile.cache
```

载荷先检查本次随机标记，再将 `volatile.cache` 移到同目录的 `volatile.cache.disabled-<run-id>`。隔离成功后才从电脑临时服务下载恢复文件，写入 `volatile.cache.restore-<run-id>` 并核对 SHA-256。请保持电脑及临时服务运行，直到收到恢复结果。

- 下载或校验失败：报告 `CACHE_RESTORE_FAILED`，不写 root 证明文件、不启动 SSH，保留 `.disabled-<run-id>` 供人工检查。已隔离的副本不再处于启动消费者读取的位置，下次开机不会自动执行它。失败下载还可能留下 `.restore-<run-id>` 临时文件，清理前应核对实际内容与本次记录。
- 隔离未完成：报告 `CACHE_ISOLATION_FAILED`，停止后续操作。先确认原启动文件及隔离路径的实际状态，不能根据该错误声称已经隔离或恢复。
- 备份校验成功：以不带强制覆盖的 `ln` 原子创建原缓存路径。若等待网络期间新的投递已经占据原路径，就保留新缓存和本次隔离副本、清理本次恢复临时文件，并报告 `CACHE_IDENTITY_MISMATCH`；不会强制覆盖那个新文件。成功恢复后移除本次临时文件和隔离副本。

恢复下载本身没有自动重试循环。电脑端命令结束会关闭对应临时服务；再次冷启动不能代替人工恢复或新的受控投递。启动身份回报使用的有限重试属于另一阶段，不代表恢复文件会自动重试成功。每次只进行一轮受控投递，避免多份工具重叠修改启动文件。

未提供备份时，载荷在清理前检查本次随机标记；不匹配时报告错误并停止。移除本次载荷不等于将一个无备份的旧文件恢复成原样。

## 已有 root SSH 时

先读取当前文件与运行标记，确认这是本次残留，再清理；不要盲目删除系统文件、整个缓存目录或其他人的启动配置。涉及的主路径是 `/mnt/lg/cmn_data/var/cache/volatile.cache`（在验证设备上对应 `/var/cache/volatile.cache`）。具体标记和本次写入位置以工具输出及载荷源码为准。

当前整理版的写入清单如下，`<run-id>` 和 `<sha256>` 由每次运行的实际值决定：

| 位置 | 用途 |
| --- | --- |
| `/mnt/lg/cmn_data/var/cache/lg-root-probe-<run-id>.txt` | `probe` 探测文件 |
| `/mnt/lg/cmn_data/var/cache/volatile.cache` | `stage` / `ssh` 的一次启动载荷；运行后按标记清理或恢复 |
| 同目录 `volatile.cache.disabled-<run-id>` | 提供备份时隔离的本次载荷；失败后可能保留，需人工检查 |
| 同目录 `volatile.cache.restore-<run-id>` | 下载备份时的临时文件；根据恢复结果清理 |
| `/mnt/lg/cmn_data/var/cache/lg-root-proof-<run-id>` | 启动身份记录 |
| `/home/root/.ssh/authorized_keys` | `ssh` 按完整行去重追加用户自己的公钥；不清空原文件 |
| `/home/root/.local/libexec/lg-webos-c4-root/dropbear-<sha256>` | 用户提供并校验过的 SSH 服务器 |
| 同一二进制目录中的 `.part-<run-id>` 文件 | 未完成的临时下载；出现时先核对本次记录 |
| `/mnt/lg/cmn_data/var/cache/lg-root-ssh.pid`、`lg-root-ssh.log` | SSH 进程记录与启动日志 |
| `/var/lib/webosbrew/sshd` | 为兼容服务器构建创建的目录；保留其中原有内容 |

如果启用了 `ssh`，个人公钥、提供的服务器文件和运行中的服务器属于额外写入。确认对应进程并停止后，再按本次清单移除自己新增的文件或密钥行；保留原有 SSH 配置和其他授权。目录和授权文件的权限会分别设为 700 与 600。用户提供的 Dropbear 在 `-R` 下生成主机密钥的位置由其构建决定，需自行记录，工具不会统一覆盖已有主机密钥。不要在唯一可用的恢复通道尚未确认前直接移除它。

## 尚无 root 通道时

保留投递结果和冷启动回报，先判断失败发生在哪一阶段。仅凭界面无变化、电脑没有收到回报或 2323 端口不通，不能推出缓存文件不存在。停止反复尝试，使用自己事先准备并验证过的现场恢复途径。

本项目不提供能够修复任意启动失败的通用恢复镜像或承诺，也不修改只读系统分区来安装固件。系统恢复或更新可能影响现有数据与兼容性，需依据对应设备的实际状态处理。

## 电脑端

结束临时服务后，配对数据与运行产物保留在本机忽略目录。完成调查前保留自己需要的记录与原始备份；对外分享时只保留经过人工检查的错误文字和结果摘要，不包含回调凭据、网络地址、密钥、主机指纹或完整电视日志。
